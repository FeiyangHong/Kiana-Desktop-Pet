# 琪亚娜独立桌宠 · 中文使用与迁移指南

版本：0.7.4。适用 Windows 10/11 x64，需 .NET Framework 4.8（较新的 Windows 通常已经具备）。

这是独立运行的桌宠程序，不是 ChatGPT 插件。关闭 ChatGPT 后仍可使用换装、触摸、走动和作息功能；AI 对话尚未启用。

## 从 Git 仓库在两台电脑构建

本仓库保存同一份源码、素材、测试和联动组件。每台 Windows 10/11 x64 电脑克隆或拉取后，在仓库根目录运行：

```powershell
.\build-release.ps1
```

脚本使用本机 .NET Framework 编译器，生成 `dist/Kiana-Desktop-Pet-0.7.4-Windows/`、对应完整 ZIP 和 SHA-256 安装清单。安装时双击生成目录里的“安装独立桌宠.cmd”；已有安装会备份旧版并保留本机设置。仅想编译并生成解压目录时可加 `-NoZip`。

以后在一台电脑修改 `source/` 或素材，先运行构建和相关测试，再提交并推送；另一台先拉取，再运行上述构建脚本并安装。两台同时修改时使用分支合并，不用文件同步覆盖源码。两台电脑各自保存 `settings.json`、显示布局、日志和联动会话；如需同步通用偏好，用桌宠设置中的导出/导入预览。

这是公开的非官方个人同人项目。原创代码的许可证见 [LICENSE](LICENSE)，角色素材及第三方组件的权利边界见 [ASSET_NOTICE.md](ASSET_NOTICE.md) 和 `licenses/`。MIT 授权不适用于角色素材。

偏好导出和设置页现在使用同一程序版本号；构建与运行状态也由统一版本常量提供，避免升级后仍显示旧版本。

## 0.7.3：区分 Mini 连接与通知来源

当 Mini 页面已经连接，但当前任务只在 ChatGPT 主窗口提供时，设置会显示“Mini：正常”和“通知：备用来源可用”，说明两者的实际状态。桌宠继续从主窗口读取这项任务；这不表示聊天和语音入口断开。

## 0.7.2：适配新版 ChatGPT Mini 活动卡片

新版 ChatGPT Mini 不再提供旧的宠物状态标记时，桌宠会从 Mini 自身的聊天、语音及活动卡片识别连接和任务状态。活动卡片中的运行、等待、失败和完成状态可用于同步，避免仅因旧标记消失而显示“Mini 未同步通知”。点击桌宠通知入口时会展开已存在的 Mini 活动，不会误触“隐藏活动”。如果 ChatGPT 以后再次调整 Mini 页面结构，设置中仍会如实提示联动状态。

## 0.7.1：效果预览、联动状态与双设备导入检查

### 设置中的效果预览

右键桌宠 → **设置 → 效果预览**：点击蓝色处理中、绿色完成未读、灰色断线、橙色等待或空闲状态，查看本页的模拟角标。预览使用当前衣装和现有矢量图标，不写真实任务列表、不改变已读状态、不连接或启动其他应用。

- “按当前设置试播完成提醒”遵守提示音开关、气泡开关、普通完成静默及当前免打扰/隐藏状态。默认普通完成静默开启，因此只出现绿色角标，这是正常效果。
- 若要看气泡，可从本页进入通知设置，关闭普通完成静默与全局静默、开启气泡，再返回试播；倒计时使用当前停留秒数。
- “试听提示音（仅此一次）”是明确的一次试听，不修改声音开关。声音使用 Windows 系统提示音，系统音量或静音会影响播放。
- 离开页面、关闭设置或点击停止会结束气泡计时；真实联动继续运行。

### 联动详情与异常提示

**设置 → ChatGPT 联动** 分别显示聊天入口、语音入口、通知来源的可用性与最后成功时间。没有未读消息时，正常的通知来源仍会显示可用；缓存与超时不显示为新鲜同步。语音入口可用只说明按钮可访问，实际通话仍受麦克风权限等条件影响。

应用运行期间，持续异常或备用来源超过 30 秒只提示一次；错误类型变化不会重复弹出，稳定恢复 20 秒后才允许下一次独立异常提醒。主动关闭应用/联动不提示，静默、免打扰或隐藏期间不补播旧异常。每次启动桌宠重新观察；详细原因始终可在设置中查看。

### 通知列表保持阅读位置

点击铃铛打开统一通知中心，按“需要处理、正在进行、完成未读、已读记录”分组。刷新复用任务卡片，保留筛选、滚动位置和键盘焦点；任务跨组时仍保留同一张卡片。任务删除或跳转被禁用时，焦点安全回到筛选控件。ChatGPT 已读任务由其实际状态移出列表，本地已读任务进入已读记录。缺少任务更新时间时显示“来源未提供”，不拿轮询时间冒充。

### 两台电脑如何同步

1. 两台电脑分别安装 `Kiana-Desktop-Pet-0.7.1-Windows.zip`；已有桌宠也可以在“场景与维护 → 从完整 ZIP 更新程序”查看版本变化后更新。
2. 在作为来源的电脑进入 **设置 → 体验 → 双设备偏好与备份**，选择“导出通用偏好（适合另一台电脑）”。
3. 将 JSON 传到另一台电脑，选择“导入并预览差异”。窗口展示当前版本、设置包来源版本与导出时间，并逐项列出当前值和导入后值。
4. 默认只合并通用偏好；启动选项、全局快捷键、联动方式、应用名单、显示布局记忆开关及屏幕坐标保持本机值。完整偏好备份可在预览中分别勾选导入本机配置或屏幕位置。
5. 点击“备份并应用 N 项修改”后才生效；取消/关闭不修改设置。包内没有的旧版选项保留本机值，未知新版选项显示跳过数量。应用前自动备份至 `preference-backups`。

通用导出不携带本机应用名单、启动选项及坐标。完整备份适合恢复同一台电脑；连接会话、软件安装路径、实际显示布局记忆和日志始终不在偏好包里。若两边都改过设置，先比较预览，选定一次导入的来源；导出时间不是自动冲突裁决，不进行后台双向云同步。两台电脑同时改代码时，仍需先合并共同源码，再分别安装构建出的完整包。

测试脚本见 `tests/v071/Run-Tests.ps1`，覆盖分功能健康状态、异常提示节流、缺失字段合并、本机配置保护、取消导入、预览隔离与计时、任务插入/跨组时的滚动及焦点保持。以下保留历次版本说明；当前入口与默认行为以本节为准。

## 0.7.0：启动、通知与显示恢复

右键桌宠 → **设置**，新增或调整了以下入口：

| 位置 | 用法与默认值 |
| --- | --- |
| 启动与联动 | 分别选择是否随桌宠启动 ChatGPT、网易云音乐，**默认均关闭**。仅下次启动桌宠时执行，已经运行的应用不会重复启动；导入偏好后同样下次启动生效。 |
| ChatGPT 联动 / 启动与联动 | “检查并修复联动”先重新检测，仅修复 ChatGPT 会话或 Mini；不会重启网易云、强制关闭 ChatGPT 或清空输入。普通方式运行的 ChatGPT 如需重建连接，请按启动器提示从托盘退出。 |
| 通知中心 | 完成提醒停留 2–30 秒（默认 6 秒）、提示音（默认关）、全局静默、普通完成静默。已有静默偏好保持；要显示完成气泡，请关闭“普通任务完成静默”，并开启桌宠气泡。 |
| 通知中心 | 短断线保留 10–120 秒（默认 30 秒）；角标变灰、列表标注最后同步时间，重连前任务跳转停用。主动关闭 ChatGPT、关闭联动或保留到期后清除显示。 |
| 铃铛 | 统一查看 ChatGPT 与本地任务，按来源、状态、未读筛选，显示任务标题、状态和更新时间。原生通知入口在列表上方。 |

诊断明确区分“应用未运行”“会话变化 / 端口不可用”“Mini 未同步或未响应”“备用状态”。备用状态说明正在使用主窗口已加载的本机任务，不代表 Mini 的所有功能都正常。原生 Mini 计数优先，不叠加两路 ChatGPT 计数。备用状态范围仍受客户端已加载任务限制。

静默提醒保留铃铛，抑制气泡和声音。首次连接不补播已有完成提醒；短断线恢复不会重复提醒相同完成状态；免打扰结束仍尊重普通完成静默。通知中的任务标题只保存在内存，不写入状态文件。关闭通知中心不等于已读，打开对应 ChatGPT 任务后由 ChatGPT 更新已读状态。

菜单、提示框、设置按钮和任务卡片使用统一字体、圆角和间距；工具栏与音乐栏统一淡入淡出节奏。继续使用透明窗口适用的文字渲染、布局取整及矢量图标，保持原有素材和平滑采样。

显示器变化、DPI 变化、工作区变化、解锁与唤醒后，会取消未完成拖动和走动，延迟复核布局，再修复宠物、自由音乐栏坐标及置顶层级。唤醒后分三次检查，兼容显示器较晚恢复；手动隐藏、免打扰和外部菜单让层规则保持生效，不强制显示宠物。显示布局记忆仍只保存在当前电脑。

**迁移**：将 `Kiana-Desktop-Pet-0.7.0-Windows.zip` 完整复制到另一台 Windows 电脑并解压，双击“安装独立桌宠.cmd”。需要同步偏好时，旧电脑在设置中导出，新电脑导入；默认不带屏幕坐标。两台电脑各自安装完整新版，勿同步正在使用的安装目录或联动会话文件。桌面仍只创建“琪亚娜桌宠”一个入口。详细双设备同步和备份步骤见下文。

测试：`tests/v070/Run-Tests.ps1` 在隔离目录验证默认值、迁移、定向修复规则、断线到期、通知去重、任务列表、DPI 渲染及显示恢复。100% / 125% / 150% / 200% 图片为渲染检查，不等同于物理拔插或实际休眠测试；不同显卡、扩展坞及混合 DPI 设备仍需实机观察。`tests/v066` 回归菜单层级恢复，`tests/v067/notification-source-tests.cjs` 验证通知来源脚本。

## 0.6.7：恢复 ChatGPT 消息状态

- 检查 Mini 的原生打开状态，避免把关闭后残留的页面误判为正常同步。后台模式开启时会重新准备 Mini；没有状态回复时按超时处理。
- 优先显示原生 Mini 的通知。Mini 没有角标时，读取 ChatGPT 主窗口已加载的本机任务元数据，补充显示蓝色“思考中 / 处理中”、绿色“完成未读”、橙色“等待回应”和红色“失败”。

## 0.6.6：修复菜单关闭后漏恢复与闪烁

沿用 **设置 → 外观与互动 → 托盘面板和外部菜单优先显示**。

- 宠物与音乐栏通过同一批 Windows 层级操作同步调整，不再分别切换 WPF 的置顶属性，减少所属窗口之间的相互影响。
- 打开菜单或隐藏图标面板时，直接排在面板后面，并使用面板所在的窗口层级。置顶面板后面的宠物不必降到所有普通应用下面；非置顶自定义菜单则按它的层级让位。
- 菜单关闭后只保留约 24 毫秒的短合并窗口，随后恢复置顶；取消此前约 180 毫秒的额外等待。实际时间仍受系统事件和调度影响，不承诺所有设备逐帧零延迟。
- 恢复时复核 Windows 实际置顶标记；即使窗口自身属性仍显示置顶，也会修复丢失的实际标记，不再依赖下一次前台应用变化。
- 不把已被 DWM 隐藏的面板算作仍然打开，不再仅因残留菜单模式标志而持续让位。
- 层级切换不调用隐藏 / 显示、不改位置和透明度、不抢焦点。原有全屏、锁屏、手动隐藏及免打扰规则保留。

验证包括：8 次连续展开 / 关闭面板、两个窗口的实际层级、可见状态和坐标、模拟置顶标记丢失后的自动恢复、标准菜单与自定义菜单、子菜单、异常退出。测试及记录在 `tests/v066` 和 `0.6.6校验记录.json`；v064/v065 为历史行为测试。

此版本原迁移包为 **Kiana-Desktop-Pet-0.6.6-Windows.zip**，升级保留偏好。参考 Windows 的 [SetWindowPos 窗口所属关系规则](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)；该规则说明了一个所属窗口的置顶变更可能影响其他关联窗口。

## 0.6.5：菜单与隐藏图标面板优先（层级实现已由 0.6.6 修正）

**本版替代 0.6.4 的“菜单打开时隐藏”行为。现在只临时取消置顶，不主动隐藏桌宠。**

入口：**设置 → 外观与互动 → 托盘面板和外部菜单优先显示**，沿用上版开关的选择，默认开启。

- 打开托盘软件右键菜单，或点击任务栏小箭头展开“隐藏的图标”面板时，宠物与音乐栏临时取消置顶，并排在已识别的菜单 / 面板之后。工具栏和气泡随宠物处于相同层级。
- 保持显示状态和屏幕坐标，不调用隐藏来避让；菜单期间暂缓走动，已显示的工具栏和音乐栏保持原位。作为普通层级窗口，此时也可能被其他应用窗口自然遮住。
- 关闭最后一个菜单或隐藏图标面板后，自动恢复宠物和音乐栏置顶，不抢键盘焦点，不改变 ChatGPT 等其他应用的置顶标记。
- 从隐藏图标面板再打开软件右键菜单，或进入子菜单时继续让位；不会因只关闭一个子菜单就提前恢复到最前。
- 手动隐藏、锁屏、全屏和免打扰仍按原设置处理。关闭面板不会把原本隐藏的宠物强行显示出来。

适配 Windows 10 / 11 的托盘隐藏图标窗口类型，保留标准菜单和托盘自定义弹出菜单检测。独立进程测试验证可见性、原坐标、实际置顶标记、菜单前后顺序、子菜单及面板关闭恢复。不同应用版本的特殊自绘菜单仍可能需要进一步适配。

完整迁移包为 **Kiana-Desktop-Pet-0.6.5-Windows.zip**，更新方式同下文；旧偏好保留。验证记录见 `0.6.5校验记录.json`，当前菜单行为测试为 `tests/v065/Run-Tests.ps1`；v064 留作旧版“隐藏”行为的历史测试，不用于验证当前行为。

## 0.6.4：系统托盘和外部菜单优先（历史行为，已由 0.6.5 替代）

默认开启：**设置 → 外观与互动 → 外部菜单打开时临时隐藏桌宠**。

外部右键菜单打开时，宠物、气泡、ChatGPT 工具栏和音乐栏一起暂时收起，避免覆盖菜单或拦住鼠标。菜单关闭后恢复原来的屏幕位置；常驻音乐栏恢复，悬停音乐栏仍按原规则出现。菜单打开期间停止走动和层级修复，恢复后略作停留。

- Windows 标准菜单和常见 Windows Forms 弹出菜单直接识别，包括托盘软件的标准右键菜单。
- 对于自定义菜单，检测系统托盘 / 隐藏图标面板上的右键操作，再识别附近新出现的无边框弹出窗口。无需修改 Clash、QQ、微信、网易云、WPS、飞书或 ChatGPT。
- 子菜单仍开着时持续避让，关闭最后一个菜单后短暂停顿再恢复；菜单进程异常退出也会自动恢复。
- 桌宠自己的右键菜单和托盘菜单排除在外。手动隐藏、锁屏、全屏隐藏及免打扰隐藏优先，不因菜单关闭而被解除。
- 开关随偏好迁移、支持撤销。旧偏好升级后默认启用，关闭此开关即可恢复之前的显示行为。

实现仅读取窗口类型、边界、可见状态和托盘右键事件，不读取菜单文字、不执行菜单命令、不记录鼠标轨迹，也不修改其他软件的置顶设置。退出桌宠会释放事件和鼠标监听。

兼容边界：已验证标准 Win32 菜单和独立进程的 WPF 自定义弹出菜单；每个软件的不同版本不保证使用相同菜单实现。直接绘制在原窗口内、没有单独弹出窗口和菜单事件的特殊菜单，可能需要额外适配。托盘上方少量延迟恢复用于防止子菜单切换时闪现。

记忆保存在本机设置目录的 display-layouts.json，不随偏好包导出，不建议跨设备同步。可以清除旧布局记忆，清除后会重新记住正在使用的布局。手动拖动会保存，自由走动中的位置约每八秒保存一次，位置不变时不重复写入。

### 通知和后台开销

“普通任务完成静默”默认开启，普通完成保留铃铛，失败和等待仍提醒。短时间的本地任务通知按来源与任务 ID 合并，默认等 5 秒统一提醒，可调 2–30 秒；免打扰、隐藏或锁屏期间积累，恢复后给摘要。ChatGPT 的状态变化也使用桌宠的静默/摘要规则，不改变原生通知的已读状态，不读取聊天正文。

开启资源优化后，活动和悬停约 30 帧/秒、普通空闲约 10 帧/秒、休息约 5.6 帧/秒、隐藏约 2 次/秒；仍保留必要的显示和唤醒检查。状态文件降低写入频率，音乐栏位置没有变化时不重复移动窗口。

断线重试逐渐延长，最长 30 秒；手动重新检测连接可立即重试。已连接 ChatGPT 始终保持约两秒同步，防止后台 Mini 隐藏租期过期。音乐栏在隐藏和锁屏时降低读取频率。这些是调度上的优化，不代表已经测得固定比例的省电或 CPU 降幅。

### 主题、尺寸与封面配色

- 外观与互动 → 主题：浅色、深色或跟随 Windows 应用主题，覆盖桌宠工具栏、气泡、右键菜单、音乐栏及设置页主体。系统原生下拉框、标题栏和文件选择器可能继续沿用 Windows 自己的样式。
- 外观与互动 → 工具栏大小：75%–150%，与宠物尺寸独立。放大后会预留相应空间，音乐栏继续避让整个宠物窗口。
- 音乐 → 封面配色：独立开关和 0–100 程度，0 为中性色，100 仍是柔和色调。默认 20。只对已经加载的封面取色，没有额外的封面请求；缺少封面使用中性淡紫。切换时轻微过渡，文字和按钮使用固定的高对比度颜色。

### 新增日常动作

三套圆润 Q 版新增整理头发、伸懒腰，各两张绘制关键帧，共 12 张；运行帧为 384×416 真透明 PNG，继续使用已确认的明亮眼神和清晰线条。眨眼复用原有闭眼帧。普通三套复用已有挥手、开心等动作，没有另行绘制。

空闲动作约每 35–80 秒选择一次，不连续重复相同动作；走动、拖动、任务忙碌、设置或菜单打开、悬停操作、睡眠和免打扰时不插入。右键“互动与休息”可主动整理头发或伸懒腰；可在外观页关闭自动日常动作。连续单击互动有约 0.7 秒防抖，避免不断重启动画。

原图和内置 image_gen 的生成提示词在“日常动作原图”，总览为“日常动作预览.png”。图集只进行工程裁切和统一缩放排版，保留透明度，不采用锐化或重绘来伪造细节；同一套动作使用相同缩放比例。

### 程序更新、回退与偏好恢复

1. 将另一台电脑发布的完整 ZIP 复制到本机。
2. 场景与维护 → 从完整 ZIP 更新程序，选择包后等待 SHA-256 校验，查看目标版本和版本说明。

4. 想退回旧程序时，选择“回退到本机程序备份”；默认只回退程序，可勾选同时恢复当时的偏好。

本功能没有自动云同步或合并两台源码；仍按下文“一份共同源码、两份本地安装”的方式维护。修改来源代码后仍需构建、测试并重新生成发布清单。

## 两台设备的持续更新与同步

当前支持手动选择完整 ZIP 更新，没有自动云同步、自动下载更新或冲突合并功能。以下流程用于同一个人维护两台 Windows 10/11 x64 电脑；这个 EXE 不能直接用于 macOS、手机或平板。

### 首次迁移

将完整 ZIP 传到新电脑、全部解压并运行安装器即可。六套服装、新动画、源码及 ChatGPT 平滑联动组件都在包内，不需要把旧电脑的 AppData 或整个 ChatGPT 数据目录搬过去。ChatGPT 登录和 Mini 联动按本文单独设置。

若要复制服装、大小、作息等偏好，推荐使用「设置 → 使用说明」的导出与导入按钮，默认保留各自的屏幕位置。也可在两边退出后备份并手动复制 `文档\Codex\PetTools\KianaDesktopPet\settings.json`。原始配置包含坐标，不适合在两台运行中的电脑之间实时双向覆盖。

以后要在另一台继续修改程序，请保留完整解压目录，使用其中的 `source/` 和 `assets/`。已安装的 `文档\Codex\PetTools\KianaDesktopPet\app` 只是运行副本，不包含完整开发源码。另一台的助手应先读这份 README；仅登录同一账号并不能保证本地项目文件同步。

### 推荐：一份共同源码，两份本地安装

| 内容 | 同步方式 |
| --- | --- |
| C# 源码、构建脚本、图集、素材授权、安装器、说明 | 放在同一个 Git 仓库，两台各自检出到普通本地开发目录。 |
| 测试通过的完整安装包 | 按版本保存，例如 `Kiana-Desktop-Pet-0.2.5-Windows.zip`；通过共享位置或移动存储传递，在另一台重新运行安装器。 |
| 服装、尺寸、作息等 `settings.json` | 默认各台独立保留；想统一时选定一台作为来源，导出通用偏好，在另一台导入并预览差异，默认保留本机配置及坐标。 |
| 屏幕坐标、日志、`status.json`、`show.request`、`exit.request`、备份目录 | 留在各自电脑，不做双向同步。 |
| 平滑启动器的 `session.json`、调试端口会话、快捷方式、安装路径 | 各台重新生成，不复制旧电脑的运行会话或快捷方式。 |

每次继续修改前，先获取共同仓库的最新代码。为这次功能建一个分支，修改、验证后提交并推送；合并回主线后统一确定新版本，重新构建并发布完整 ZIP。另一台先退出桌宠，再安装同一版本即可，安装器会保留那台的偏好设置。

如果两台同时修改：A、B 各用一个功能分支，先合并其中一份，再让另一份吸收最新主线、解决冲突并重新验证；不要用“修改时间较新”的整文件直接覆盖另一份改动，也不要强制推送覆盖共同主线。图集等二进制图片不能像文字代码那样逐行合并，同一张图最好由一台修改，或保留两个候选版本后选择。Git 的分布式工作方式参见 [Git 官方说明](https://git-scm.com/book/en/v2/Distributed-Git-Distributed-Workflows)。

开发目录、发布包存放位置和实际运行目录分开。不要让网盘实时同步正在运行的整个安装目录或 Git 内部文件；共享位置用于传递已经生成的 ZIP。

### 暂时不使用 Git

可以采用“轮流维护”：A 更新完成后，打出带新版本号的完整包，B 接收并以它作为下一次修改的起点；B 改完再回传。一次只让一台修改，旧包保留用于回退。只要存在同时修改或长期分叉，就改用上面的分支合并流程。

### 给另一台电脑助手的维护要求

> 先读取项目 README，确认最新源码版本和未提交改动。修改完整项目中的 source/、assets/，不要直接修改已安装 EXE。保留六套宠物、平滑采样及现有通知和菜单行为。完成相关验证后，统一更新版本号和变更说明，重新构建程序、生成 package-manifest.json 中的 SHA-256 清单并打出完整版本化 ZIP。升级时保留本机 settings.json，使用本机路径与联动会话。如果共同仓库已有更新，先合并，不能直接覆盖。

`source/build.ps1` 只负责编译。仓库根目录的 `build-release.ps1` 会根据 `release-files.json` 重新生成完整安装清单和 ZIP。新增发布文件时，也要将它加入 `release-files.json`，否则安装包不会包含它。

## 故障排查

**双击无响应：** 先看系统托盘，程序限制为单实例，再次打开会尝试找回已有宠物。确认 ZIP 已完整解压，且未单独移动 EXE。若提示缺少 .NET Framework，请安装 4.8。

**宠物不见了：** 退出全屏，双击托盘图标；检查是否开启鼠标穿透或手动隐藏。更换显示器后也可通过托盘找回。

**出现两只宠物：** 检查“设置 → ChatGPT 联动 → Mini 后台运行”是否开启。连接成功后原 Mini 外观会自动收起，独立桌宠仍从它获取状态。

**联动未就绪：** 通过平滑启动器启动 ChatGPT，开启独立桌宠的联动与 Mini 后台模式；若提示后台未准备好，在 ChatGPT 设置中显示 Mini 一次。程序区分后台页面尚未准备与启动器连接失效。不要手动打开公网调试端口。

**图像看起来大小不同：** 睡觉时为横向侧卧，头发和身体布局会变化。大小设置是逻辑尺寸，也受 Windows 显示缩放影响；平滑采样不会给旧图集增加原本没有的细节。

**设置损坏：** 程序会保留损坏文件副本，并使用默认设置。可退出程序后恢复备份。

日志位置：用户文档目录 `Codex\PetTools\KianaDesktopPet\desktop.log`。运行状态：同目录 `status.json`；该文件只含动作、皮肤、隐藏原因和联动状态。

## 0.3.0：网易云音乐小卡片

### 第一次连接

1. 右键桌宠 → **音乐与工具栏 → 连接网易云音乐**。
2. 如果网易云已经以普通模式运行，连接窗口会保留，提示从网易云托盘菜单选择“退出”。退出后它会自动重新启动客户端；不需要退出 ChatGPT。
3. 在网易云音乐中播放歌曲，宠物旁边会显示歌名、歌手和三个播放按钮。约一秒内同步当前状态。
4. 下次仍通过这个入口打开网易云。直接双击原版网易云快捷方式，可能无法建立连接。更新或重新安装网易云后，入口会重新从注册表查找安装位置。

歌曲、歌手、暂停状态及播放进度来自本机网易云音乐客户端。三个按钮调用客户端播放栏自身的上一首、暂停／继续、下一首按钮；不发送全局媒体按键，不会控制浏览器或其他音乐播放器。

音乐栏会跟随宠物，在当前屏幕边缘自动调整位置；鼠标停留在卡片上时宠物暂停走动。关闭网易云、隐藏宠物、进入全屏应用或在右键“音乐与工具栏”子菜单选择“收起音乐栏”，卡片会隐藏。设置的“音乐”页可以重新开启。

### 歌词和封面

歌词默认关闭。点击卡片右侧的三行图标，或在设置 → 音乐中打开“显示同步歌词”，即可展开单行歌词。歌词按客户端播放进度同步，切歌后会清空上一首的歌词。界面使用原生字体和矢量按钮，阴影不作用于文字；出现和换行采用短暂淡入，不缩放文字。

启用歌词后，程序用当前歌曲 ID 向网易云 `music.163.com` 请求 LRC；封面使用客户端给出的网易云图片地址并请求小尺寸图片。无需另行登录或提供 Cookie。请求失败时显示“歌词暂不可用”，纯音乐或无歌词曲目会提示暂无歌词；封面失败时显示音符。歌词仅暂存在内存中，不写入运行记录。本地歌曲、播客或无法匹配 ID 的曲目可能没有歌词。

此接口不是网易云面向第三方承诺稳定的开放 API，客户端版本或接口变动可能需要更新适配。当前实测客户端为 **3.1.29.205104**。迁移到不同版本的电脑后，需再次确认播放控制可用。

### 连接方式与迁移

使用客户端自身的本机调试接口，监听 `127.0.0.1:9436`。程序验证监听进程的安装路径、仅本机监听地址及网易云主页面后才连接。只读取播放器相关字段；不读取登录凭证、私信或听歌历史。最终版本不依赖 BetterNCM / InfLink-rs，也没有向网易云安装目录保留注入 DLL。

另一台电脑安装当前完整迁移包后，使用桌宠菜单中的“连接网易云音乐”。在该电脑单独安装并登录网易云，按上面的步骤连接即可；不要复制本机快捷方式、客户端缓存、账户数据或调试会话。两台设备仍按本说明前面的源码版本管理方式同步。

## 0.3.5：快捷键开关与自定义

旧版将快捷键标为 Ctrl + Alt + P，但错误使用了 Ctrl + Shift 的 Windows 标志，实际占用了 Ctrl + Shift + P。本版已修正；新安装和从旧版升级均默认关闭全局快捷键，避免干扰 VS Code 等应用。

右键宠物 → 设置 → 快捷键：

1. 选择 Ctrl、Alt、Shift 修饰键及主键，至少包含 Ctrl 或 Alt。
2. 点击“保存组合键”；关闭状态也能保存偏好，不注册按键。
3. 勾选启用后立即生效；取消勾选立即释放，无需重启。

目前唯一全局动作是“找回宠物”。注册新组合失败会显示冲突原因，并保留此前有效绑定；程序退出时注销绑定。系统只能检测其他程序注册的全局快捷键，无法自动识别 VS Code 等应用内部的局部快捷键，因此请主动避开 Ctrl + Shift + P 等常用组合。ChatGPT 和网易云自己的快捷键仍在各自应用中管理；菜单与联动面板内的 Esc 不属于全局快捷键。

通过 19 项 Windows 原生注册与配置检查，以及 5 项真实设置页交互检查，记录见 `快捷键校验.json` 和 `快捷键设置页校验.json`。包含旧配置默认关闭、正确修饰键映射、真实冲突保留旧绑定、更换与关闭立即释放、退出释放，以及设置页保存和开关行为。

## 0.3.6：减少连续同向走动

连续两次向同一方向走后，下次有空间就向反方向走；其他情况下仍随机选择方向。距离继续随机为 65–235 像素，接近边缘时缩短，边缘向内避让优先于反向规则。没有移动空间时不累计次数。手动拖动、找回宠物或重新启动后重置方向记录。
