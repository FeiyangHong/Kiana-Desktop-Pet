# 可选连接方式（0.8.15）

默认仍是原有页面联动。设置里的连接方式分别保存在本机，通用偏好导出不包含它们。切换、重新检测和自动回退均不会结束或重启 GPT、网易云。

## 选择方式

| 设置位置 | 方式 | 提供的能力 |
| --- | --- | --- |
| ChatGPT 联动 → ChatGPT 连接方式 | 原有 Mini / 页面联动 | 保留原有 Mini、主窗口通知、聊天、语音和任务跳转 |
| 同上 | 本地 Hooks | 普通启动后同步本地任务的运行、待处理、回合结束、中断及待确认状态；不提供云端任务、聊天、语音或任务跳转 |
| 同上 | 自动 | 原有连接不可用时回退 Hooks；原有连接恢复后优先使用原有来源 |
| 音乐 → 网易云连接方式（可展开） | 原有播放器页面联动 | 保留当前播放器页面提供的歌曲 ID、播放进度、歌词与副歌能力 |
| 同上 | Windows 系统媒体 | 普通启动后读取歌名、歌手、封面、播放状态，点击按钮时执行播放控制；有条件补充本地记录里的 ID 与总时长 |
| 同上 | 自动 | 优先页面，连接不可用时回退系统媒体 |

原有默认值未修改。Hooks 不使用 Mini，因此它的 Mini、主窗口状态显示“此方式不使用”，相关入口禁用；不会循环提示修复这些本来就不提供的能力。

## Hooks 注册与恢复

1. 在已安装桌宠的设置中点击“注册 / 更新本机 Hooks”。程序将接收器的稳定安装路径注册到用户 `.codex/hooks.json`；现有配置先备份到桌宠运行目录 `connections/config-backups/`，保留其他 Hooks 和原有 `notify`。
2. 在 GPT 的 Hooks 设置审核并信任指向 `KianaHookReceiver.exe` 的 7 项定义：SessionStart、UserPromptSubmit、PermissionRequest、PostToolUse、Stop、Interrupt、SessionEnd。首次注册或命令定义改变后需要人工信任，这是 GPT 的要求；不需要重启 GPT。
3. 选择 Hooks 或自动方式。首次收到本地任务事件后显示已连接。

接收器采用同步命令，先将元数据写入独立临时文件、刷新到磁盘并原子提交，再退出。它不输出内容、不作审批决定，失败也不改变原任务结果。两个 Windows Shell 均会等待控制台接收器退出，避免异步 Stop 在临时会话退出时被取消。

状态按会话和回合合并，重复事件去重；同一回合的中断、结束优先于迟到的运行或待处理事件。只展示每个任务最新回合，上一回合晚到的结束事件不能覆盖新回合。带调用 ID 的审批与工具完成事件按 ID 配对；缺少 ID 时保持保守状态，直到结束或转为待确认。

桌宠保存元数据检查点，重启后重放事件。若回调缺失，只读恢复**已注册、会话 ID 相符**的本机 `.codex/sessions` 或 `archived_sessions` 日志末尾最多 2 MiB 中的 `task_started`、`task_complete`、`turn_aborted` 状态证据；不接受未写完的末行。当前 GPT 版本没有传递可选 `transcript_path` 字段，因此还会每 30 秒按 Hooks 已知会话 ID 查找对应日志文件名，仅打开该会话的日志；本机当前桌面对话已验证定位与读取成功。只另存编号、状态、时间和日志定位信息，不展示或另存提示词、工具参数、对话正文。

`Stop` 只表示**回合已结束**，不代表任务成功。中断不报成功；缺少结束证据且会话关闭、或超过五分钟没有回调及日志更新，显示“状态待确认”。立即中断可能让 GPT 在调用开始钩子之前取消它：真实测试中收到了 Interrupt / SessionEnd，而没有 SessionStart / UserPromptSubmit；即使只有中断证据也会正确结束运行状态。未信任、接收器被强制终止、磁盘写入失败或没有可读日志时，不能承诺完全不丢事件，缺失证据不会被补成成功。原生 Hooks 的同步、异步及信任机制见 [官方说明](https://learn.chatgpt.com/docs/hooks)。

## 网易云的 ID 与进度

系统媒体没有网易云歌曲 ID。适配器仅以 SQLite **只读连接**读取 `%LOCALAPPDATA%/NetEase/CloudMusic/Library/webdb.dat` 的最新播放记录，要求歌名与完整歌手或主歌手精确匹配（只整理首尾空格和 Unicode 规范形式），记录时间不得早于本次客户端进程启动，并校验 ID、时长与时间范围；系统提供专辑名时还要匹配专辑。没有匹配就留空，不联网模糊搜索 ID。

本地匹配不是系统原生 ID：系统只提供主歌手时会注明来源；同名、同主歌手的不同版本仍可能有歧义。数据库结构变化、记录尚未刷新或不匹配时会自动降级为仅显示系统元数据。

本机普通启动的客户端已验证可读取 `to be continued`、早見沙織、封面和暂停状态，并由最新本地记录补充 ID `2123750257`、总时长 `246.52` 秒。这个客户端的系统时间线仍为全零，本地持久化进度早于本次启动，UI Automation 也没有暴露进度控件，因此**当前无法可靠补齐播放位置**。没有读取进程内存、修改播放器或操作播放进度。

缺少进度时保留平时听歌动作及播放控制，明确提示无法同步歌词；不按零秒或连接时刻猜进度，不触发副歌切换，不允许在“当前位置”标记副歌。有 ID 时仍可设置本曲的平时动作。若将来客户端提供有效系统时间线，再按系统位置与更新时间恢复同步能力；原有页面方式继续使用原逻辑。
